## Contexte
J'ai un jeu à hexagones existant, développé avec Flask (backend), JavaScript (frontend) et MongoEngine (ODM pour MongoDB).

## Objectif
Ajouter la notion de joueur au jeu, avec authentification via Discord OAuth2.

## Tâches à réaliser

### 1. Exploration du projet
- Analyse d'abord la structure existante du projet (arborescence, modèles MongoEngine actuels, routes Flask existantes, organisation du JS front)
- Identifie comment les entités du jeu (hexagones, etc.) sont actuellement structurées pour comprendre comment les relier à un joueur

### 2. Modèle de données
- Crée un modèle MongoEngine `Player` (ou `User`) avec :
  - Identifiant Discord (discord_id)
  - Username / avatar Discord
  - Email si disponible/nécessaire
  - Date de création du compte, dernière connexion
  - Tout champ pertinent pour lier le joueur aux entités du jeu existantes (ex: hexagones possédés, score, etc.)
- Réfléchis à la relation entre `Player` et les entités de jeu existantes (référence, ownership, etc.)

### 3. Authentification Discord OAuth2
- Mets en place le flow OAuth2 Discord complet :
  - Route de redirection vers Discord pour autorisation
  - Route de callback qui récupère le code, l'échange contre un token, puis récupère les infos utilisateur Discord
  - Création ou mise à jour du joueur en base à partir des infos Discord
  - Gestion de la session Flask (ou JWT, à toi de choisir la meilleure approche selon l'architecture existante) pour maintenir l'utilisateur connecté
- Utilise les variables d'environnement pour les secrets (CLIENT_ID, CLIENT_SECRET, REDIRECT_URI) — vérifie s'il existe déjà un système de config/env dans le projet, sinon propose d'en ajouter un (.env + python-dotenv par exemple)

### 4. Protection des routes
- Ajoute un mécanisme (decorator ou middleware) pour protéger les routes qui nécessitent d'être connecté
- Définis clairement quelles routes/actions du jeu nécessitent maintenant d'être authentifié (ex: jouer, sauvegarder une action) vs celles qui restent publiques (ex: visualiser la carte)

### 5. Frontend (JS)
- Ajoute un bouton "Se connecter avec Discord" qui déclenche le flow OAuth
- Gère l'affichage conditionnel selon l'état de connexion (joueur connecté vs non connecté)
- Affiche les infos du joueur connecté (pseudo, avatar) quelque part dans l'UI
- Ajoute une fonctionnalité de déconnexion

### 6. Sécurité
- Vérifie que le state OAuth2 est bien géré pour éviter le CSRF sur le flow d'auth
- Assure-toi que les sessions/tokens sont correctement sécurisés (cookies httponly, secure en prod, etc.)
- Ne jamais exposer le CLIENT_SECRET côté front

### 7. Documentation
- Documente les nouvelles variables d'environnement nécessaires dans un README ou .env.example
- Explique brièvement comment configurer une application Discord (Discord Developer Portal) pour obtenir les credentials OAuth

## Contraintes
- Respecte le style de code et les conventions déjà présentes dans le projet
- N'introduis pas de nouvelles dépendances lourdes si l'existant permet déjà de répondre au besoin (vérifie si Flask-Login, Authlib, requests-oauthlib etc. sont déjà présents avant d'en ajouter)
- Propose un plan/résumé des changements avant de commencer l'implémentation si le périmètre te semble large
